====================================
WHAT'S NEW SINCE THE LAST UPDATE (2026-08-13 -> 2026-08-17)
====================================

DELETE BUTTONS (both website and Android):
- You can now delete Clients, Job Cards, and Knowledge Base entries on
  both platforms. Deleting a Client also removes its Machines (a real bug
  fix — deleting a client with machines used to fail outright).

CUSTOMER IMPORT CAN NOW UPDATE EXISTING CUSTOMERS:
- Previously the importer could only create new customers. Now it can
  also update an existing one it recognizes (matched by code, email,
  phone, or name) — you choose per row whether to skip, update, or import
  as new. Notes are added to, never overwritten.

ANDROID — USERS & ROLES (new):
- Administrators can now view and edit user roles/permissions from the
  Android app, not just the website. Creating brand-new accounts still
  has to happen through normal sign-up on either platform — that's a
  deliberate security decision, not a missing feature.

ANDROID — CONNECTION STATUS FIXED:
- The "Connection and Sync Status" screen was actually checking an old,
  no-longer-used system in the background. It now genuinely checks the
  real database, so it can't show "Connected" during a real outage or
  "broken" when everything's actually fine.

ANDROID — OLD BACKEND FULLY REMOVED:
- The Android app's old backend system (Firebase, the thing it used to
  run on before the switch) has been completely and verifiably removed.
  Both apps now run on exactly the same database, nothing split anymore.

ANDROID — NEW SETTINGS SCREEN:
- Administrators can now configure Job Card settings (numbering, default
  status, which statuses/line types are available) and manage the
  Products & Services catalogue directly from the Android app — the same
  thing the website's Settings page already did, now on your phone too.

ANDROID — LIGHT/DARK APPEARANCE:
- The Android app can now switch between a light look, a dark look, or
  automatically follow your phone's own setting. Before this, it only
  ever had one dark look with no way to change it.

A REAL BUG FOUND AND FIXED TODAY — "silent failure" on denied saves:
- Found and fixed a subtle issue: in one specific scenario (an
  administrator's permission being taken away while they still had a
  settings screen open on the app), the app could have shown "Saved
  successfully" even though the save was correctly blocked. No customer
  data was ever at risk — the security check itself was always working
  correctly, this was purely about the app being honest with the user
  about what actually happened. Found through direct testing against the
  live database, fixed, and re-tested — confirmed working now.
